## What we are buying an answer to

Does agent-generated code need a portable, vendor-neutral evidence object?

## Kill / success (behavior, not stars)

Distribution failure ≠ product failure. Stars do not count.

| Signal | Meaning |
|---|---|
| Weak | stars, likes, “cool idea” |
| Interesting | someone else runs the CLI once |
| Strong | repeated receipts from someone else |
| Very strong | **3+ external teams wire it into a private-repo CI/PR** |
| Exceptional | ask for org policy, signing, retention |
| Commercial | ask what hosted/team support costs, or pay |

**Kill** if by 2026-09-12 we have nothing at **Strong** or above, **or** inbound is only “cool research,” **or** the product slides into a scanner / reviewer / governance suite.

Ten random installs < three recurring private-repo users.

## Do not build before the market earns it

No Sigstore, GitHub App, dashboard, hosted product, SLSA project, or enterprise policy engine during this clock.

Maturation *if* Very strong / Commercial appears later: v0 JSON+hash → PR integration (already there) → signed receipt → optional in-toto/Sigstore predicate. Not now.

## Not this

Receipts don’t determine whether AI-generated code is good. They record what evidence accompanied the run that produced it.
